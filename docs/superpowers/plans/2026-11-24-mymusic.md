# MyMusic Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser app (Chrome/Edge, Windows) where a guitarist keeps a repertoire (Bildiğim / Çalıştığım), and records audio or video takes per song after a metronome count-in, optionally playing along with a backing track that is mixed into the recording, all saved as plain files in a folder the user picks.

**Architecture:** Static SPA (Vite + React + TS) hosted on GitHub Pages; no backend. Pure domain logic (`src/domain`) and pure audio planning (`src/audio/*Plan.ts`, state machine) are unit-tested; browser APIs sit behind thin adapters (`FsDir` over File System Access API, `RecordingEngine` over Web Audio + MediaRecorder). One `AudioContext` per take does metronome, backing track (to headphones via `setSinkId`) and the recorded mix (`MediaStreamAudioDestinationNode`).

**Tech Stack:** Vite 5, React 18, TypeScript 5 (strict), Vitest + @testing-library/react + jsdom, `idb-keyval` (folder handle persistence). No other runtime deps.

**Spec:** `docs/superpowers/specs/2026-11-24-mymusic-design.md` — read it before any task.

## Global Constraints

- Target: Chrome / Edge (Chromium ≥ 110) on Windows. Firefox/Safari/mobile out of scope; show a Turkish "Bu uygulama Chrome veya Edge gerektirir" screen if `showDirectoryPicker` is missing.
- All UI text Turkish.
- Mic constraints: `echoCancellation: false, noiseSuppression: false, autoGainControl: false, channelCount: 2, sampleRate: 48000`, plus `deviceId: { exact }` when chosen.
- Video default `width 1280, height 720, frameRate 30` (ideal, not exact).
- `MediaRecorder` `audioBitsPerSecond: 256000`, `timeslice: 1000` ms.
- Defaults: `countInBeats 4`, track `volume 0.7`, `startSec 0`; pre-roll 150 ms; auto-stop 2 s after track ends.
- BPM integer 30–300; count-in beats integer 1–16.
- Folder layout: `mymusic.json`; `recordings/<songFolderName>/`; recording files `YYYY-MM-DD_HH-mm-ss_video.webm` / `YYYY-MM-DD_HH-mm-ss_ses.webm` (local time); backing track `track.<ext>` in the song folder; in-progress parts under `.parcalar/<recordingId>/`.
- Metronome clicks must never reach the recorded stream. Backing track does reach it (delayed by latency compensation).
- No network calls besides loading the app itself. No analytics.
- Deleting a song never deletes files.

## Review Focus

1. Song titles with characters illegal on Windows (`AC/DC`, `?`, `:`, trailing `.`) or Turkish letters → folder name is safe and readable (Task 1 slug tests).
2. `mymusic.json` missing, empty, hand-edited with unknown fields, or corrupt JSON → missing = empty library; unknown fields survive a save; corrupt is never silently overwritten (Task 1 + Task 4 tests).
3. Folder permission lost or folder deleted between sessions → reconnect screen, no crash (Task 4 test).
4. Space pressed while typing in an input, or pressed again during count-in → no accidental start/stop (Task 7 shortcut tests).
5. Track file deleted in Explorer, or start point past the track's end → clear Turkish message; take still records without the track (Task 8 test).

Engine graph (one `AudioContext({ sampleRate: 48000 })`, `setSinkId(outputDeviceId)` if given and supported):
- Clicks: oscillator bursts (accent 1500 Hz, others 1000 Hz, 30 ms) at `planCountIn` times → `ctx.destination` only.
- Mic: `createMediaStreamSource(input)` → `MediaStreamAudioDestinationNode` (recorded). Not to `ctx.destination` (user monitors through Voicemeeter).
- Track: two `AudioBufferSourceNode`s from the same buffer, both `offset = startSec`, through a `GainNode(volume)`: one → `ctx.destination` started at `downbeat`; one → recorded destination started at `downbeat + latencyMs/1000`. `onended` of the headphones source → after 2 s, `TRACK_ENDED`.
- Recorded stream = recorded destination's audio track + `input`'s video track (video kind). `MediaRecorder(stream, { mimeType: pickMimeType, audioBitsPerSecond: 256000 })`, `start(1000)` at `recorderStart` (setTimeout aligned to `ctx.currentTime`); each `dataavailable` → `ChunkWriter.append`; stop → `finalize`; cancel during count-in → no writer created (writer starts at `recorderStart`).
- File name `recordingFileName(now(), kind)`; recordingId `crypto.randomUUID()`.
